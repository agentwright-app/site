What happens on every request

A general SaaS boilerplate gives you sign-in and payments. It does not know what a cache read costs, which price was in effect last month, or how to stop a user before their next agent turn. This is the path every message takes here.

  1. Sign-in check. No session means 401. lib/auth/index.ts
  2. Rate limit per plan: a sliding window in Postgres, 429 with Retry-After when exceeded. No Redis. lib/ratelimit/index.ts
  3. The conversation is loaded or created, scoped to the signed-in user. app/api/agent/route.ts
  4. A model without a price row is refused before any tokens are spent. lib/billing/metering.ts
  5. The monthly plan cap is checked before every model turn. lib/agent/loop.ts
  6. Claude streams the answer. The cache breakpoint sits on the system prompt and tools are sorted by name, so the cached prefix stays stable. lib/agent/tools.ts
  7. Every turn is recorded: four token counts, the cost in integer micro-dollars, and the id of the price row that produced it.
  8. Tool calls of one turn run in parallel and go back in a single message. A failing tool returns an error the model can read.
  9. The loop stops after 12 turns.
  10. The browser receives typed server-sent events: meta text tool_call tool_result usage error done

Who is behind this

Agentwright is a small independent business with one product. Most of the code and docs are written with Claude, the way the kit expects you to work. What keeps that honest: every release passes a type check, unit tests, a Postgres integration test and a production build in CI, every change is in the changelog, and you can read the code before you pay. Support is by email at hello@agentwright.app. We usually answer within one business day.

What is not included

  • Organizations, teams and seats. Accounts are single users.
  • Stripe or Paddle. Billing is wired for Lemon Squeezy and Polar. Another provider means writing its webhook route and checkout calls; metering and caps read your own database.
  • Charging for overage. A plan can be allowed past its cap. Creating the charge is yours.
  • A conversation list. The API resumes a conversation by id; the chat UI does not list past ones yet.
  • A marketing site or component library. The UI is plain on purpose.
  • Other model providers. It is built on the Anthropic SDK, not on a multi-provider layer.

Why not build it yourself?

You can. Our blog shows how each part works, for free. The parts, one by one, with the post for each. The kit is those parts already integrated, tested together, and kept current when Claude prices and SDKs change.

A general SaaS boilerplate gives you more screens and more integrations. It leaves the Claude-specific work to you: cost per request, price history, caps between turns, cache-stable tool lists. Nine kits side by side, with sources, and one-to-one with ShipFast, AnotherWrapper and Vercel's free Chatbot template.

The Claude Agent SDK is a good fit for agents that run on your machine or in a container. For a multi-user web app with metering you usually want your own loop. We compared them, with code.

Questions before you buy

What do I need to run it?

An Anthropic API key, a Postgres database (Neon's free tier is covered in the deploy guide; any Postgres works) and a GitHub OAuth app for sign-in. A Lemon Squeezy or Polar account is only needed once you charge your own users. Your API and hosting costs are your own.

How is it delivered? Do I get a GitHub repository?

Right after payment you get an email from hello@agentwright.app with your license key and a download link for the source as a zip file. There is no repository access: you put the code in your own private repository. If the email has not arrived after a few minutes, check spam or write to us.

Can I use Polar or Stripe instead of Lemon Squeezy?

Polar: yes, since version 0.5.0, with one setting (the Polar guide). Stripe: yes, but you write that part. The provider-specific code is a webhook route and a few files in lib/billing/. Metering, plan caps and the rest of the app read your own database, so they stay the same.

{{KIT_MODELS}}. Switching models is one environment variable; a model that is not in the price table needs one new row.

What does one license cover?

One person, or one team working for the same company or client. You can build as many products as you like with it, including commercial SaaS. You can't resell or republish the kit's source.

How do updates arrive?

Every new version is free for license holders. The changelog lists each release, and your download link serves the current version.

Is the code written with AI?

Yes, mostly. Agentwright is built with heavy help from Claude, and every release has to pass the type check, the tests and a production build before it ships. You can judge the result yourself on the What's inside page.

What if it is not what I expected?

Email us within 14 days of purchase and you get a full refund. You don't need to give a reason.
